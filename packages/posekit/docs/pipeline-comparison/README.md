# Pipeline comparison — 11 papers vs the posekit abstraction

`pipeline-comparison.html` is a self-contained report comparing 11 keypoint/mocap
pipelines (MEgATrack, UmeTrack, Kineo, EPFL Smart Kitchen, AssemblyHands,
AssemblyHands-X, MAMMA, EgoExo-Hands, SHOW3D, HO-Cap, Look Ma No Markers) as DAGs
of computation nodes, and derives the abstraction posekit should implement. It is
the evidence base behind `../design.md` (v3): the survey confirms the role
taxonomy with four amendments (camera-aware crop as a first-class node,
`TopDownFeatureEncoder2d`, temporal feedback as a seam, regress-vs-optimize fit).

**View it:** open `pipeline-comparison.html` in a browser. Figures and DAG SVGs
are embedded; the only network dependency is the `marked` CDN used by the two
collapsed markdown sections (full proposal + posekit inventory) — everything
else works offline.

## Contents

| Path | What |
| --- | --- |
| `pipeline-comparison.html` | The report (regenerated by `build.py`; do not edit by hand) |
| `build.py` | Generator: JSON + figures → HTML. Needs Graphviz `dot` on PATH (pixi global) |
| `json/result.json` | Output of the original 9-paper agent workflow: per-paper extractions (`papers`), canonical stage taxonomy + stage×paper matrix (`taxonomy`), posekit inventory (`inventory` md) and abstraction proposal (`proposal` md) |
| `json/new-paper*.json` | Papers added after the workflow (Look Ma = `new-paper.json`, SHOW3D = `new-paper-2.json`). Same schema as `result.json['papers'][i]` **plus** `matrix_cells` (their stage×paper matrix row) and `rebuild` (their "as posekit" one-liner) |
| `figures/<id>.png` | Pipeline figures cropped from the papers' PDFs (visually verified) |

Source PDFs are not stored; every paper's link is in `LINKS` inside `build.py`.

## How it was made

A 21-agent workflow (one extract + one adversarial-verify agent per paper, a
posekit code-inventory agent, and two synthesis agents for the taxonomy/matrix
and the proposal), followed by a Codex review pass. Figures were extracted by
rendering PDF pages with `pdftoppm` and cropping via its `-x/-y/-W/-H` region
flags (coordinates are pixels *at the render DPI*). DAGs are rendered by
Graphviz from the verified node/edge lists — node colors encode canonical roles
(see the legend in the report), feedback edges are detected as DFS back edges.

## Adding a paper

1. Produce `json/new-paper-<N>.json` matching the sibling schema (copy a
   `result.json['papers']` entry as reference). Required extras for add-on
   papers: `matrix_cells` (all 10 stage ids: capture, detect, identity, crop,
   pose2d, lift3d, calibrate, fit, verify, feedback) and `rebuild`. The proven
   agent protocol: download PDF → `pdftotext` → extract stages/edges/traits from
   the method section → crop the pipeline figure with `pdftoppm` (view the PNG
   to verify the crop is complete) → adversarially self-verify against the text.
   Node `role` values must come from: detect, track, segment, identity, pose2d,
   dense-landmarks, lift3d, triangulate, calibrate, fit-model, optimize,
   render-verify, temporal, crop/rewarp, other.
2. Save the verified figure as `figures/<id>.png`.
3. In `build.py`: add the id to `PAPER_ORDER` (placement = page order), and
   entries in `SHORT` and `LINKS`. New papers are auto-discovered from the
   `new-paper*.json` glob; header/hero counts update automatically.
4. Hand-maintained survey ratios do **not** auto-update — grep `build.py` for
   `/11` and revise where the new paper moves a count (fisheye-rewarp need,
   parametric-fit tail, camera-aware-crop gap, etc.).
5. `python build.py` regenerates the HTML in place.

Caveat: `taxonomy.commonalities/divergences` full-text (inside the "Full
analysis" collapsibles) and the `proposal`/`inventory` markdown are frozen
9-paper synthesis artifacts; the headline compressions in `build.py` are the
maintained layer. If the add-on papers start invalidating them, rerun the
synthesis stage of the workflow over all papers.
