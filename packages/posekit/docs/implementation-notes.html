Deviations

Edge cases that forced a deviation from design.md; conservative option taken, logged here.

  • SAM3 prompts are text-only. The design table lists boxes/points/text for PromptableSegmenter; SAM3's single-image API is concept-prompted, so box/point prompts raise ValueError with a clear message. Conservative option: keep the SegmentationPrompts type general and defer box/point support to the planned SAM2 image-mode implementation rather than bolt visual prompting onto SAM3's tracker head.
  • mv-api "lightweight" preset remapped. posekit carries no rtmpose-s checkpoint, so lightweight now pairs yolox-tiny with rtmpose-m (documented at MODE_PRESETS). Every mv-api caller in the repo uses the default wholebody, which is weight-for-weight identical to before.
  • SAM2 image-encoder TRT deferred. Phase 2's "TRT for the SAM2 image encoder" is not included: the EfficientTAM-ti torch path already sustains ~38 fps in the composed demo, and carving the encoder out of the stateful predictor is an invasive change best done against a measured multi-camera bottleneck (Kineo's case). Logged as follow-up, not silently dropped.
  • IdentityEncoder signature. Design says "crops → embeddings"; implemented as (frames, detections) → embeddings so the crop stays on GPU inside the role (the crops-array version would force callers back through numpy). Same information, stricter residency.
  • mv-api frame boundary resolved — the exoego pipeline now decodes exo videos with torchcodec on CUDA and feeds the tracker NHWC tensors directly (gpu_decode=True default); the BGR numpy path remains as the fallback for CPU-only hosts and non-torchcodec readers.
  • rtmlib Hand solution left as planned zoo entries. The RTMDet-nano hand detector's mmdeploy graph has a different topology than YOLOX; the NMS-strip surgery is untested there, so the entries are registered with status="planned" instead of shipping an unvalidated path.
