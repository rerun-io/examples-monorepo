MV API port architecture review

Make the exo/ego pipeline modular enough to test and reuse

The current full_exoego_pipeline.py works as a runnable HoCap/LG validation path, but it combines dataset loading, model construction, calibration, tracking, hand refinement, Rerun logging, and visual validation in one surface. This map shows the exact execution path, then aligns it with the create-node recipe.

Current shape One CLI module with helpers plus a large model-backed orchestration function.
Correct target A composite app that orchestrates several single-purpose nodes.
Main risk Rerun side effects and model calls are mixed with array transforms, which hides test seams.
Validation need Stage outputs must be screenshotable per 2D view, not only saved as one full RRD.

Current Pipeline

This is the execution path in packages/mv-api/src/mv_api/api/full_exoego_pipeline.py as it exists now. The important observation is that nearly every step logs to Rerun or constructs heavyweight models inside the same call stack.

CLI config selects the dataset and model parameters

RRDPipelineConfig wraps RerunTyroConfig, a Tyro dataset union, MultiViewCalibratorConfig, MultiviewBodyTrackerConfig, optional calibration timestamp, and max_frames.

Entry point: tools/run_exoego_full.py -> main(config)

Dataset setup produces the exo/ego sequence

config.dataset.setup() returns a BaseExoEgoSequence with exo readers, ego readers, optional dataset cameras, timestamps, and the world coordinate system.

Adapters: HocapConfig, SyncedVideoExoEgoConfig

Rerun scene scaffolding is created up front

The pipeline logs the world coordinate system, COCO-133 annotation context, video streams, and the initial blueprint using setup_scene() and send_scene_blueprint().

Side effects: rr.log(), rr.send_blueprint()

Calibration timestamp and frames are selected

The calibration timestamp defaults to the last shortest timestamp. Exo frames and RGB ego frames are read through frame timestamp lookup, converted from BGR to RGB, and filtered to RGB ego streams.

Helpers: timestamp_to_frame_index(), _read_bgr_frame(), _bgr_to_rgb()

Calibration inputs are resized and joined

Exo and selected ego RGB images are resized to 1280x720. The code keeps original frame shapes so calibrated pinholes can later be scaled back to native video resolution.

Constant: CALIB_TARGET_RESOLUTION

Model-backed calibration runs

WilorHandKeypointDetector and MultiViewCalibrator are instantiated inside the orchestration function. The calibrator returns pinholes, point cloud, optional depth maps, and calibration artifacts.

Models: WilorHandKeypointDetector, MultiViewCalibrator

Pinholes are split, named, scaled, and optionally replaced

Calibrated cameras are split into exo and ego sets, renamed from log paths, scaled to native image dimensions, and replaced with dataset-provided pose cameras when both exo and ego cameras exist.

Helpers: _scale_pinhole_to_image_shape(), _dataset_exo_pinhole_params()

Scene geometry is logged

The pipeline logs pinholes when using calibrated cameras, a downsampled environment point cloud, and a TSDF-fused mesh when depth outputs are available.

Side effects: log_pinhole(), rr.Points3D, rr.Mesh3D

Exo multiview body tracking predicts 3D COCO-133

MultiviewBodyTracker runs over synchronized exo frames. The loop filters to upper body, face, and hands, thresholds confidence, logs 3D points, projects them back into exo camera views, masks out-of-bounds points, and logs 2D overlays.

Function: predict_kpts3d_from_calibrated_videos()

Ego projection and hand refinement run per frame

The 3D result is projected into ego camera trajectories. Invalid depth is masked, hand bboxes are computed, WiLor refines left/right hands when bboxes are valid, and final ego 2D overlays are logged.

Helpers: compute_square_bbox(), _extract_wilor_uv(), _mask_points_outside_intrinsics()

The recording is flushed

The CLI returns only after the Rerun recording stream flushes. The current public API returns None, so downstream checks have to inspect RRD files or monkeypatch internals.

Final call: recording.flush(timeout_sec=30.0)
Boundary Actual data contract Why it matters
Dataset -> scene setup BaseExoEgoSequence with exo/ego sequence objects and reader collections. Good domain boundary, but validation code still reaches directly into nested reader details.
Scene setup -> model pipeline SceneSetupResult with log paths and shortest timestamp. This should become a typed PreparedScene record to isolate timestamp and log-path rules.
Calibration -> pose stages MVCalibResults plus split/scaled camera lists, point cloud, and optional depth maps. Calibration data is transformed inline, so tests cannot assert camera normalization separately.
Exo tracking -> ego refinement list[Float32[ndarray, "n_kpts 4"]] where columns are XYZ confidence. This should be a result dataclass with timestamps and skeleton metadata, not a bare list.
Compute -> Rerun Most stages call rr.log() directly during computation. Final-result logging should be shared helpers; intermediate logging should be verbose-gated.

Test seams are indirect

Existing tests have to monkeypatch model constructors, readers, or internal functions because there is no stable public stage API for calibration, exo pose, ego projection, or Rerun logging.

Side effects hide data bugs

The 2D alignment issue only became obvious through screenshots. A stage result should expose counts such as finite points, in-frame points, invalid depth points, and bbox validity per view.

Models are built inside the run

WiLor, the calibrator, and body tracker are constructed in the full pipeline call. That makes reuse, app streaming, and fake model injection harder than needed.

Full pipeline is not a node

A node should wrap one model or algorithm. This full path combines several algorithms, so it belongs in apps/ as a composite orchestrator after the nodes are extracted.

Create-Node Alignment

The referenced recipe defines a node as a single-purpose CV unit with three layers: API, Gradio UI, and entry points. It also makes a strong distinction between reusable nodes and composite apps that orchestrate multiple nodes.

Recommendation: do not turn full_exoego_pipeline.py into one large node. Keep the full workflow as a composite app, and extract model-backed, testable nodes underneath it.

Modularity Plan

The useful split is not by file size. It is by runtime contract: each stage gets typed inputs, typed outputs, isolated model ownership, and one shared final-result logger.

Prepare Scene

Dataset setup, readers, log paths, timestamps, RGB stream selection.

Calibrate Views

Image resize, model calibration, camera scaling, point cloud and mesh outputs.

Track Exo Pose

Multiview body tracking, 3D skeletons, exo 2D projections.

Refine Ego Hands

Ego projection, invalid-depth masking, bboxes, WiLor refinement.

Log and Validate

Shared result loggers, blueprints, RRD save, per-view screenshots.

Interface sketch for the first extraction 
from dataclasses import dataclass
from pathlib import Path

from jaxtyping import Float32, Int, UInt8
from numpy import ndarray
from simplecv.camera_parameters import PinholeParameters


@dataclass(slots=True)
class PreparedScene:
    """Dataset-derived scene inputs for full exo/ego processing."""

    exo_video_log_paths: list[Path]
    """Rerun log paths for exo video streams."""
    ego_video_log_paths: list[Path]
    """Rerun log paths for ego video streams."""
    shortest_timestamp: Int[ndarray, "n_frames"]
    """Common timeline used by the pipeline."""
    ego_rgb_indices: list[int]
    """Indices of ego streams treated as RGB inputs."""


@dataclass(slots=True)
class ExoPoseResult:
    """Tracked and projected COCO-133 pose outputs from exo views."""

    timestamps_ns: Int[ndarray, "n_frames"]
    """Timestamps for each pose frame."""
    xyzc: Float32[ndarray, "n_frames n_kpts 4"]
    """World-space XYZ plus confidence for each keypoint."""
    exo_uv: Float32[ndarray, "n_frames n_views n_kpts 2"]
    """Projected exo pixel coordinates after image-bound masking."""
    finite_counts: Int[ndarray, "n_frames n_views"]
    """Number of finite projected 2D keypoints per frame and view."""

Test Strategy

The goal is to avoid only proving that the command exits. Each stage should produce inspectable typed results before it writes to Rerun, then the Rerun artifact and screenshots should validate that the viewer actually represents those results correctly.

Tier Scope Example assertion Uses real models?
T0 import Package, APIs, CLI wrappers. import mv_api and each node module succeeds under mv-api-dev. No
T1 pure helpers Timestamps, camera scaling, projection masking, bbox clipping. Off-image points become NaN; clipped bbox never leaves intrinsics bounds. No
T2 node units One node at a time with fake calibrator/tracker/WiLor. Node returns typed result arrays and diagnostics with expected shapes/counts. No
T3 app integration Full app with fake nodes and tiny real readers. Orchestrator calls stages in order and passes camera/timestamp contracts correctly. No
T4 artifact integration HoCap sample and LG sample one-frame saves. RRD exists, has expected entity paths, and per-view screenshots show in-frame overlays. Yes
T5 UI E2E Future Gradio node/app surfaces. Upload examples, run, stream non-empty Rerun bytes, and screenshot rendered viewer. Optional

HoCap acceptance

  • Run the one-frame pipeline against the raw HoCap sample.
  • Save RRD and screenshots for each named exo/ego 2D view.
  • Assert 2D overlays are in-bounds after masking and no view autoscale is dominated by bogus coordinates.

LG acceptance

  • Run the synced-videos path against /mnt/8tb/data/exoego-self-collected/lg/....
  • Record finite/in-frame counts per ego view as diagnostics.
  • Treat zero finite ego keypoints as a stage output to debug, not just a visual anomaly.

Extraction Order

This order keeps behavior anchored to current RRD artifacts while creating testable contracts one at a time. Each step should start with a characterization test, then the smallest extraction that keeps HoCap and LG smoke runs green.

Characterize current outputs

Keep the existing HoCap/LG one-frame RRD files and per-view screenshots as comparison artifacts. Add a small script that records entity paths and finite 2D counts.

Extract scene preparation

Pull dataset setup, log path extraction, timestamp selection, ego RGB filtering, and initial frame reads into a pure-ish builder with fakes in tests.

Extract camera and projection utilities

Move scaling, timestamp mapping, BGR/RGB conversion, projection masking, and bbox clipping into small modules that carry existing unit tests.

Create the calibration node

Wrap MultiViewCalibrator in a node class, return CalibrationResult, and move point cloud/mesh logging into log_multiview_calibration_result().

Create the exo pose node

Wrap MultiviewBodyTracker, return batched XYZC and exo UV results, and expose confidence, in-frame, and hand-validity diagnostics.

Create the ego refinement node

Wrap WiLor and ego projection, return bboxes plus refined UVs, and make invalid-depth and zero-finite cases first-class diagnostics.

Rename the full workflow as an app

Move the workflow launcher to tools/apps/full_exoego_app.py and keep a temporary legacy CLI alias if needed for existing validation commands.

Add UI only after API contracts settle

Build node UIs and a composite app UI following the recipe once the result dataclasses, loggers, and blueprints stop changing.
