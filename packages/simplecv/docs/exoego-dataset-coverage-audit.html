SimpleCV ExoEgo dataset coverage audit

For each dataset registered in the ExoEgo framework: where the data truly comes from, every label the original release ships, what the SimpleCV loader parses, what actually reaches Rerun — and how to close the gaps.

TL;DR — the five systemic gaps

  • Object / item poses are the biggest hole. HOCap ships per-frame 6DoF poses for 64 textured object meshes inside the NPZ files we already download and open; HOT3D ships mocap-grade 6DoF poses for 33 UV-textured GLB objects; Aria Gen2 ships 293 3D bounding boxes with 6DoF scene-object poses. The schema has no /world/gt/objects vocabulary, so all of it is dropped.
  • Segmentation masks are never logged. HOCap (SAM2 masks in the same NPZs), MAMMA eval (per-person SAM PNG tars), and Aria Gen2 (COCO-RLE hand/object interaction masks) all ship them; no entity path exists.
  • Eye gaze is downloaded and thrown away. HOT3D's mps_eye_gaze is in the download list but never parsed; EPFL's gaze is sitting in holo_data_wpose.csv we already open; Aria Gen2 gaze (with vergence depth + pupil + blink) is in the VRS we already have.
  • Depth support exists in the framework but is mostly unwired. Only HOCap logs depth. EPFL ships Kinect depth MP4s (videos_depth/) that the loader ignores; Aria Gen2's FoundationStereo depth is skipped at download time.
  • Action / language labels have no home. Assembly101 (1M fine + 100K coarse segments + mistake labels), EPFL (60K verb–noun segments), EgoDex (per-episode LLM task descriptions), Aria Gen2 (diarized transcripts) — none of it reaches the recording.

Schema fixes — what exoego:v2 needs to grow

The framework (base_exoego.py, rerun_rig_logger.py, docs/exoego_schema.md) handles cameras, video, depth, COCO-133, MANO, SMPL-X, and environment meshes well. Everything in the red/amber columns above is blocked on missing vocabulary — there is no entity path or label container for objects, segmentation, gaze, actions, or multi-person keypoints. Proposed additions in green:

Label-container changes (Python side)

  • ObjectStack on ExoEgoLabels: names: list[str], world_T_obj: Float32[ndarray, "n_frames n_objs 4 4"], optional mesh paths / Asset3D blobs, optional per-frame validity. Mirrors how ManoStack/SmplxStack already work — one stack per label family, batch-logged columnar.
  • People axis for xyzc_stack ("n_frames n_people 133 4") or a list[…] per person — the TODO already written at base_exoego.py:68-72. MAMMA is the forcing function.
  • GazeStack: origin + direction (+ optional vergence depth, pupil, blink), timestamps on its own timeline.
  • ActionSegments: starts_ns, ends_ns, verb, noun, text, flags — logged as ranged rows so the viewer timeline shows segment bands.
  • Depth for EPFL needs no schema work at all — populate the existing exo_depth_list from videos_depth/.
Documentation debt (exoego_schema.md + the simplecv.datasets catalog page)
  • docs/exoego_schema.md documents cameras/video/keypoints/MANO/SMPL-X/IMU-reserved, but has no sections for objects, segmentation, gaze, point clouds, or actions — add them as the vocabulary lands, with the same validation-rule rigor as the rig sections.
  • The tailnet catalog page (simplecv-datasets/, built from commit 4c3757a, 2026-06-25) still describes the deprecated v1 flat layout (/world/ego, /world/exo) in its schema panel, and lists MAMMA as a "research candidate" although it landed as a registered exoego dataset in PR #61. Its HOCap entry also claims object_pose is a logged modality — aspirational, not true yet.
  • The v1 RRDSequence reader can't read v2 rig-layout output; worth a deprecation note wherever v1 register tasks are documented.

Suggested order of attack

Ranked by user-visible value per unit of work. Items 1–3 need zero new downloads — the bytes are already on disk.

  1. HOCap object poses S

    Read obj_poses/obj_class_names from the NPZs the loader already opens, add ObjectStack, log transforms under /world/gt/objects. Even boxes-without-meshes immediately shows what the hands are interacting with. Follow up with the mesh mirror.

  2. EPFL depth S

    Wire videos_depth/ into the existing exo_depth_list/DepthImage path. Pure plumbing; HOCap is the working template.

  3. EPFL + HOT3D eye gaze S

    EPFL gaze is in a CSV we already parse; HOT3D gaze is in a directory we already download. One small GazeStack + a ray entity under the ego rig covers both, and generalizes to Aria Gen2.

  4. HOT3D objects + assets M

    Parse the object pose GT already in the download, add HOT3D Assets (33 UV-textured GLBs) to the fetch list, log Asset3D + pose streams. This turns HOT3D from a hand demo into the hand-and-object dataset it actually is.

  5. Multi-person keypoints M

    Lift the single-skeleton limit on ExoEgoLabels (existing TODO). MAMMA dance/multi-people is the test case; the SMPL-X forward pass for all people already runs.

  6. Segmentation seam M

    One schema addition (…/pinhole/segmentation) unlocks HOCap SAM2 masks, MAMMA eval SAM masks, and Aria Gen2 HOI masks.

  7. Actions/language seam M

    /world/gt/actions ranged segments + a static task-description property. Unlocks Assembly101's defining labels, EPFL's 60K verb–noun segments, EgoDex's LLM descriptions, and A2PD transcripts.

  8. Aria Gen2 skipped components L

    Flip on the skipped downloads one at a time (points → depth → scene boxes → HOI masks → diarization/heart-rate) as each schema seam above lands. A2PD then becomes the showcase recording for the full schema.

  9. IMU emission M

    The paths are reserved; emit gyro/accel for Robocap (calibration already parsed) and Aria/HOT3D VRS streams.
